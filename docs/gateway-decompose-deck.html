Step 2 — subsystems leave the shell

The arch review called it in the first audit: the shell runs two features that aren't wiring.

a2a_tasks.rs (1,483) → services/a2a-tasks

  • A2A task lifecycle: create/claim/complete across agents — a domain, not wiring
  • Already has its own HTTP surface (http/a2a.rs) and store access needs
  • Post-extraction: gateway/src shrinks by a subsystem; service owns its types

durable_agent_tasks.rs (1,325) → services/durable-tasks

  • Durable task queue surface — sibling of durable_work_store which already lives in stores
  • Extract with its tests; the durable work queue spec lineage moves with it

What stays in the shell (the actual job of a shell)

Composition — build groups, wire services, own lifecycles (startup order, graceful shutdown)

Routing — mount HTTP/WS routers, static UI serving

Nothing else — state/mod.rs splits: groups/ (6 files), bootstrap.rs, seeding.rs

state/mod.rs (1,888) decomposes into: state/mod.rs (~120, the composer) · state/groups/*.rs (6 × ~80) · state/bootstrap.rs (wiring + EngramStoreBundle) · state/seeding.rs (defaults) · capability_catalog.rs (already separate-ish).

Why this is next — and what it unlocks

The argument

  • Every queued feature touches AppState — session fork, parallel children, web search, Topcoat all need narrow access; today each widens the god object instead
  • It's the proven pattern — same shape as ExecCtx (35→2 fields), distillation extraction, memory engram-ification; golden-traceable, mechanical, shippable in waves
  • Review cost collapses — an AppState diff today forces reading the whole system; a StoresState diff reads itself
  • Session conventions apply: workers per wave, floors as gates, no-junk (nothing unused deleted without audit)
