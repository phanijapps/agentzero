## Blockers

**1. Doctrine safety controls are not enforced.** `gateway/gateway-services/src/ward_layout/loader.rs:174`. Archetype `ward-agent.md` content is only byte-checked and UTF-8 loaded, so unsupported placeholders, unsafe links, and prompt-injection patterns can render directly into a created ward's `AGENTS.md`, violating AC6. Fix: validate selected doctrine through an explicit whitelist/diagnostic renderer before creation and add rejection tests for unsupported placeholders, links, and injection patterns.

**2. Creation does not durably persist archetype provenance.** `gateway/gateway-execution/src/invoke/ward_layout_adapter.rs:144`. `GatewayWardLayoutAccess::create` publishes the ward and returns state without writing `WardRecord.archetype`; the only sidecar write is a later optional best-effort `WardTool` observer, so direct runtime creation and observer failure lose the durable provenance required by AC9. Fix: make the creation adapter/service write `.usage.json` with the selected archetype after successful publication before returning success.

**3. Portable registry resolution accepts case-fold aliases.** `gateway/gateway-services/src/ward_layout/loader.rs:775`. The non-Linux bounded reader canonicalizes paths and checks only vault containment, so on case-insensitive filesystems a `Coding` bundle can satisfy a request for the literal `coding` child despite AC4 requiring case-fold collisions not to select bundle content. Fix: verify each opened registry component's actual directory entry name exactly matches the closed lowercase component before reading files.

**4. Public create state reports the wrong digest.** `gateway/gateway-execution/src/invoke/ward_layout_adapter.rs:74`. The ward layout packet exposes a digest of the normalized compiled projection while discarding `CreatedWard.snapshot_digest`, so callers do not receive the digest equal to the copied `ward-conf.yaml` snapshot required by AC8. Fix: include the copied snapshot digest in the create/load state and tool result, keeping any projection digest under a separate field if still needed for staleness checks.

**5. The required transition guide is missing.** `docs/specs/ward-archetype-registry-and-creation/plan.md:116`. The plan requires `docs/guides/how-to/customize-ward-archetypes.md`, but no such guide exists, leaving AC11's documented singular-template transition unmet. Fix: add the guide covering canonical registry paths, one-time singular transition, future-ward-only edits, and corrupt-bundle failure behavior.

**6. Clean-start acceptance is not an E2E artifact.** `docs/specs/ward-archetype-registry-and-creation/plan.md:190`. The planned `e2e/playwright/full-mode/ward-archetypes.full.spec.ts` is absent, and the current fresh-vault coverage is a unit-level `AppState::minimal` test that bypasses the normal application/tool bootstrap required by AC13. Fix: add the Playwright full-mode clean-start test that boots with a fresh database/vault and creates a `coding` ward without manual fixture seeding.
