zbot storage boundary map

Current implementation inventory. “Managed by Engram” means the active semantic path is reached through zbot-engram-adapter → EngramProvider; it does not mean every old table has already been deleted.

zbot runtime

Keep: product/session execution data.

Engram managed

Keep: generic semantic memory and graph.

Retire or reclassify as upstream capabilities arrive.

Not an active production semantic source of truth.

3 · zbot adapter sidecar

zbot-sidecars.sqlite

This is the remaining competing semantic-ish store surface. It is the primary retirement target.

episodes · kg_episodesNeeds Engram episode/evidence lifecycle capability
compaction_auditNeeds Engram maintenance/operation history
recall_logNeeds generic recall/audit event capability
procedures · goals · outbox · distillation_runsClassify as zbot product/runtime data or move to an explicit generic upstream port; never a hidden semantic backend
zbot tools / UI → adapter mapping → EngramProvider capabilities → Engram backend
legacy compatibility residue

Tables still present in conversations.db

session_episodes, recall_log, memory_facts_archive, ward_wiki_articles, procedures, kg_episodes, and kg_causal_edges remain in the runtime schema for compatibility. They must be treated as legacy/migration residue, not a new semantic write target.
