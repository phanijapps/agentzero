## Blockers

**1. Rejected dynamic targets leave the parent session pending.** `gateway/gateway-execution/src/invoke/delegation_handler.rs:114`. `handle_delegation` increments `pending_delegations` before dispatch, but the new early rejection in `spawn_delegated_agent` returns after `crash_spawn_failure` without the common failure path that sends the parent callback and calls `complete_delegation`, so an invalid capability-assignment target can leave root paused indefinitely. Fix: route rejected dynamic assignments through the same failure completion path as child execution failures, and add a dispatcher/spawn-level test that asserts the parent is resumed and pending delegation count is decremented.

**2. Step executors still receive same-session agent-control tools.** `gateway/gateway-execution/src/invoke/executor.rs:1573`. The step-executor guard removes `delegate_to_agent` and `lookup_capabilities`, but `WardAgent` still allows `AgentControl`, so a step executor built with normal state-service dependencies can still receive `list_session_agents`, `handoff_to_agent`, `steer_agent`, `wait_agent`, and `kill_agent`; the current test at `gateway/gateway-execution/src/invoke/executor.rs:3448` omits those dependencies and cannot catch the leak. Fix: make the registry or actor policy mode-aware so `is_step_executor()` suppresses the full agent-control group, then test a dependency-wired step executor for all orchestration tools, not just `delegate_to_agent`.

**3. Capability audit-log verification is helper-only and tautological.** `gateway/gateway-execution/src/delegation/spawn.rs:1845`. The test constructs `capability_resolution_metadata` directly and asserts it does not contain `never-known-secret` even though that value is never provided, so raw planner/request IDs, deleted-vs-unknown reason codes, and persisted log metadata can regress without a red test. Fix: replace or supplement it with a LogService-backed intent/planner resolution test that feeds ready, deleted, disabled/OAuth, and raw unknown IDs through the runtime resolution path and asserts canonical requested/effective IDs plus closed `rejection_codes` with no raw unknown or secret-bearing values.

**4. Required end-to-end and manual verification artifacts are not recorded.** `docs/specs/execution-capabilities/plan.md:391`. T6 requires focused Rust tests, formatting, `cargo check -p gateway-execution`, `git diff --check`, the gateway full-mode E2E, and Blender/manual-audit results, but the notes directory has no command-result evidence and `engine-state.json` only says `gates-clean`, leaving AC-verification, AC-delegated-discovery, and AC-audit-logging without traceable artifacts. Fix: add the implementation evidence note with exact commands and results, including the full-mode E2E and Blender MCP/manual QA result or a documented unavailability/defer decision.
